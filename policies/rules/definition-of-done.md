# Definition of Done

**Activate:** before completion.

Done means acceptance conditions are met, required verification ran against the
current repository state, the diff is reviewed, documentation affected by the
change is current, and remaining risk is reported. Reuse an older result only
when the repository identity and relevant inputs still match. Pending approval,
unavailable required evidence, or an unresolved conflict prevents a complete
state.

The final report separates `pass`, `fail`, `skipped`, `unavailable`, and
`pending-user-action`. A screenshot is visual evidence only; frontend completion
also names applicable state, keyboard, accessibility, responsive, performance,
and browser evidence.
